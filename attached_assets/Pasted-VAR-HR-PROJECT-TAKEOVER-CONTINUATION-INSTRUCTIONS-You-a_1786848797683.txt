==================================================
SUBSCRIPTIONS
==================================================

VAR HR is a monthly SaaS product.

Plans must be data-driven.

Plans may define:

- Active employee limit
- Manager limit
- Branch limit
- Device limit
- Storage limit
- Feature access
- Advanced reports
- Payroll
- GPS
- Integrations
- API access

Do NOT hard-code plan limits.

Active employees count toward limits.

Deactivated employees remain available for historical records but should not count toward active employee limits.

When a plan limit is reached:

- Server blocks the operation.
- UI explains the limit.
- Upgrade path is shown.
- Historical data remains available.

==================================================
ATTENDANCE
==================================================

Attendance should use an event-based model.

Possible input sources:

- Web check-in
- Web check-out
- Mobile check-in
- Mobile check-out
- GPS attendance
- Biometric devices
- Authorized manual corrections

Processing:

Raw event
→ Normalize
→ Validate
→ Deduplicate
→ Apply schedule/rules
→ Calculate result
→ Audit

Raw attendance events should remain immutable.

Corrections should create correction records instead of silently rewriting history.

Attendance calculations should explain:

- Scheduled start
- Scheduled end
- Actual check-in
- Actual check-out
- Late duration
- Early departure
- Worked duration
- Overtime
- Absence
- Applied rule
- Event source

==================================================

==================================================

Possible balance events:

- Annual allocation
- Carryover
- Approved leave
- Cancellation
- Manual adjustment
- Expiration
- Policy change

Lifecycle:

Draft
→ Submitted
→ Under Review
→ Approved
→ Rejected
→ Cancelled

Approvals and rejections must be auditable.
